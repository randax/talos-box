### WSL2 host integration

WSL2 is supported in **NAT networking mode only**. Windows-side clients reach cluster names
through a PAC file and an HTTP CONNECT proxy served inside `tbxd` on one fixed Windows-loopback
port. The prototype used `5390`; the production port is intentionally left to an implementation
decision and is not fixed by this spec. The PAC sends only talosbox cluster domains through the
proxy and leaves ordinary browsing direct. The proxy resolves cluster names in-process and
connects to the selected Linux-side address without terminating TLS, rewriting SNI, installing a
CA, or exposing the cluster subnets to Windows routing. A dead proxy must abandon the proxied
request in about two seconds and must not break ordinary browsing.

`tbx windows enable` writes the current Windows user's `AutoConfigURL`; it requires no elevation.
It refuses to overwrite an occupied value, identifies the conflict, and points command-line users
at `HTTPS_PROXY` instead. NRPT and hosts-file fallbacks are ruled out: NRPT needs privileged,
mutable Windows DNS state and a reachable DNS listener, while the hosts file cannot express a
wildcard. The PAC/proxy path is the supported Windows integration.

Name coverage is exact rather than aspirational. Node names and the apiserver name resolve to
node addresses. Every other name below a cluster domain resolves to that cluster's ingress VIP,
which is permanently held by talosbox's own `lb-probe` end-state probe. The wildcard therefore
proves the talosbox ingress end state from a Windows browser; it does **not** provide name-based
access to attendee applications. Attendee workloads are reached at their own LoadBalancer
addresses by IP literal.

Two Windows users are two independent talosbox installations. Their state, PAC ownership, and
cluster domains are not shared; only the machine-wide loopback port is shared. The proxy status
path carries an opaque install id so a client can distinguish its own proxy, another user's
talosbox proxy, and an unrelated port squatter without disclosing the user or filesystem path.

The existing host-conflict subnet scan sees the WSL NAT prefix through the Linux `eth0` address
and route and continues to allocate from `172.30.0.0/16`. A new collision is skipped during
allocation. A collision discovered after a cluster already owns its subnet retains the
never-fail attached-subnet warning; on WSL2 the warning additionally offers `wsl --shutdown` as
the WSL-owned reset that can replace a stale NAT prefix. Effective mirrored mode is a `WARN`,
never a `FAIL`; it does not become a second supported networking mode.

### 4.2 Exact package API

Use these public-internal signatures (comments should state that `wslinfo` is Linux-side and `WindowsInterop` is the only Windows crossing):

```go
package wsl

type Generation uint8

const (
    NotWSL Generation = iota
    WSL1
    WSL2
)

type Observation struct {
    Value string
    Err   error
}

type Identity struct {
    Generation     Generation
    KernelRelease  string
    WSLVersion     Observation
    Distribution   Observation
    WindowsBuild   Observation
    NetworkingMode Observation
    NATPrefix      Observation
}

func (i Identity) IsWSL() bool
func (i Identity) IsWSL2() bool
func GenerationFromOSRelease(osrelease string) Generation

type ReadFile func(string) ([]byte, error)
type Command func(name string, args ...string) ([]byte, error)

type WindowsInterop interface {
    WindowsBuild() (string, error)
}

type Detector struct {
    ReadFile   ReadFile
    Command    Command
    LookupEnv  func(string) (string, bool)
    NATPrefix  func() (string, error)
    Windows    WindowsInterop
}

func Detect(deps Detector) Identity
func SystemDetector(readFile ReadFile, command Command) Detector
func NewWindowsInterop(command Command) WindowsInterop
```

Design notes:

- `Observation.Err` records why a field is unavailable for tests/logging, but the doctor formatter emits stable user text rather than embedding host-specific error strings.
- `SystemDetector` injects `os.LookupEnv`, the route/interface NAT-prefix reader, and `NewWindowsInterop(command)`. It reuses the doctor's bounded `execCombinedOutput` command seam (`cmd/tbx/doctor_routes.go:15-29`), so each subprocess retains the existing ten-second ceiling.
- `WindowsInterop` is the one interface for all WSL-to-Windows crossings. #553 gives it only the semantic method it needs. Future `tbx windows enable` work must extend this same interface with semantic AutoConfigURL read/occupied/write operations; it must not introduce direct `reg.exe`, PowerShell, or registry calls elsewhere. A semantic method is preferred over exposing generic registry syntax to every consumer.
- `NewWindowsInterop`'s concrete adapter owns both invocation and parsing. `WindowsBuild()` runs exactly:

  ```text
  reg.exe query HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion /v CurrentBuildNumber
  ```

  It trims and returns the `CurrentBuildNumber` value. Do not use `cmd.exe /c ver` or `powershell.exe -NoProfile`.
- Adding future interface methods is an intentional extension point, not authority to implement AutoConfigURL mutation, proxy status, or far-side reach in #553.

### 4.3 Detection algorithm and per-run cache

`Detect` performs these steps in order:

1. Read `/proc/sys/kernel/osrelease` through `Detector.ReadFile` and store its trimmed value in `Identity.KernelRelease`.
2. Call `GenerationFromOSRelease`: case-insensitive `microsoft` means WSL; the additional case-insensitive `wsl2` marker means WSL2, otherwise WSL1. A read error or non-Microsoft kernel returns `NotWSL`.
3. If `NotWSL`, return immediately. Do not call `LookupEnv`, `Command`, `NATPrefix`, or `WindowsInterop`. This is the hard guarantee that native Linux cannot invoke `reg.exe` or `wslinfo`.
4. On WSL, collect all independent observations even if one fails:
   - `wslinfo --version`, trim the output as an opaque Store WSL version string (do not semver-parse it);
   - `WSL_DISTRO_NAME` through `LookupEnv`;
   - `WindowsInterop.WindowsBuild()` exactly once;
   - `wslinfo --networking-mode`, lower-case and trim the effective mode;
   - for WSL2 NAT mode, derive the NAT prefix on the Linux side. If mode collection failed, still attempt the prefix so the line prints every fact available. If the effective mode is a known non-NAT value such as `mirrored`, mark NAT prefix as not applicable rather than mislabeling that interface's prefix as NAT. WSL1 also marks it not applicable.
5. Return an `Identity` regardless of partial errors; WSL detection itself is a fact, not a doctor failure.

`internal/wsl/nat.go` must derive the prefix without another subprocess or registry read:

1. Parse `/proc/net/route` and choose the `UP` IPv4 default route (`Destination` and `Mask` both zero), preferring the lowest metric if more than one exists. Its address fields are little-endian hexadecimal, not dotted-quad text; parse fixtures and any nonzero address fields accordingly.
2. Resolve that interface with an injectable interface-address source used by tests; production uses `net.InterfaceByName` plus `Interface.Addrs`.
3. Select its non-loopback IPv4 CIDR and mask the address to the network. For the observed WSL address `172.19.146.224/20`, return `172.19.144.0/20`.
4. Return an error for no default route, no IPv4 address, a host-only `/32`, or malformed route data; doctor renders the stable `NAT prefix unreadable` clause.

Add this dependency to `doctorDependencies` beside `command` and `readFile` at current `cmd/tbx/doctor.go:60-62`:

## 7. Risks, open questions, and resolved recommendations

1. **Meaning of “WSL version.”** `wslinfo --version` output may vary in decoration across Store WSL releases. Treat the trimmed non-empty output as opaque text; do not semver-parse or gate support on it. The kernel release independently establishes WSL1 vs WSL2.

2. **Localized/variable `reg.exe` output.** Parse by finding the requested value name and taking data after the registry type token, accepting CRLF and variable whitespace. Do not depend on fixed columns or English headings. One malformed result degrades only `WindowsBuild` and is never retried, preserving the one-invocation budget.

3. **NAT-prefix source.** Prefer the Linux default-route interface prefix. The research branch documents `Lxss\NatNetwork` as community/undocumented and restart-unstable; reading it would spend or complicate the single registry call and couple the check to unsupported state. The route/interface method observes the effective WSL VM network and is already visible to existing host-conflict scanning.

4. **Multiple/default routes and VPNs.** Lowest-metric UP default route is the deterministic source. If it yields no usable IPv4 subnet, report `NAT prefix unreadable`; do not guess, query Windows again, or warn. Later reachability checks can interpret VPN/mode conflicts.

5. **Mirrored mode semantics.** The INFO inventory reports `networking mode mirrored; NAT prefix not applicable`. It does not warn. The restored spec says mirrored reachability is a WARN, but that belongs to future `windows-reach`/capability work explicitly excluded from #553.

6. **Help must be runtime-conditional without Windows calls.** Determine only the WSL generation from `/proc/sys/kernel/osrelease` for help. Full identity collection belongs to the actual platform-doctor pass; otherwise `tbx doctor --help` could unexpectedly cross into Windows and native help tests would become host-dependent.

7. **Caching scope.** Cache once in `doctorDependencies`, not globally in `internal/wsl`. This both meets the one-reg-call contract and lets tests inject an identity. A daemon that later needs it should create its own startup-scoped cache from the same detector; do not make the first CLI process's observation global or persistent.

8. **Future interop surface.** A semantic `WindowsInterop` method keeps registry syntax inside one adapter. Future AutoConfigURL/far-side tickets extend that interface and its stub rather than adding a second seam. #553 must not pre-implement writes merely to anticipate them.

9. **The final CONNECT port remains undecided.** Preserve the spec's explicit statement that prototype port 5390 is evidence, not the production contract. #553 does not allocate or probe any proxy port.

10. **`docs/windows.md` is intentionally absent.** §11 defines its required future content; creating a partial guide in this PR would expand scope and risk publishing nonfunctional commands before `tbx windows enable` exists.

11. **No behavior drift in existing Linux checks.** Reusing `Identity.KernelRelease` must preserve the exact WSL/linger remediation text in `linuxSessionRefreshHint`. Bare Linux platform names, finding order after the optional first slot, levels, and command behavior stay unchanged.

With these recommendations, implementation has no unresolved decision that should block either agent.
