# Implementation plan: issues #535–#536

Drafted by gpt-5.6-sol (high reasoning), reviewed and amended by Claude Fable 5. Amendments
are marked **[amended]** and override the corresponding section below.

## Amendments

### WP4 firmware roots — drop the `brew --prefix` exec **[amended]**

Root 2 (`$(brew --prefix qemu)/share/qemu`) spawns Homebrew at daemon start and is redundant:
root 1 (the symlink-resolved binary's sibling `../share/qemu`) already covers the live Cellar
and the Nix store, and roots 3–4 cover the stable Homebrew opt paths. Remove `brewPrefix` from
`qemuDarwinProbeDeps`; the candidate list stays pure path construction.

### WP1/WP2 — `TBX_HYPERVISOR` must reach a launchd-managed `tbxd` **[amended]**

On macOS `tbxd` runs under launchd, so an env var exported in the user's shell never reaches
it. Whatever mechanism `TBX_DISABLE_BALLOON` uses today to reach the daemon on each platform
(systemd-run `--setenv` allowlist on Linux; the launchd plist `EnvironmentVariables` written
by `tbx system install`/restart on macOS, if that is how it is done) is extended with
`TBX_HYPERVISOR` in exactly the same way, and `docs/macos.md` states how to set it. If no such
macOS mechanism exists, add `TBX_HYPERVISOR` (and only it) to the plist's
`EnvironmentVariables` when set in the environment of the `tbx system install`/`restart`
invocation, and say so in the docs. The e2e battery's section C/D uses that path.

### WP2 status column — keep `--quiet` untouched, put HYPERVISOR after DOMAIN **[amended]**

Column order: `CLUSTER SUBNET DOMAIN HYPERVISOR TALOS NODE ...` so the cluster identity
columns stay where existing eyes and tests expect them. Render an empty cell (not `-`) for a
daemon that omits the field, matching how other optional cells render in `output.go`.

### WP2 doctor — no new rendering shape **[amended]**

Keep the existing per-backend line from `hypervisorFindings` byte-compatible and only append
`; remediation: <text>` inside the `availability=unavailable (...)` parenthesis when the daemon
supplied one. `default=yes (source=...)` already exists; do not restyle it.

### Verification — Linux compile check **[amended]**

`GOOS=linux CGO_ENABLED=0 go test -exec=/usr/bin/true ./...` may not compile cgo packages;
the required Linux gate is `GOOS=linux go vet ./...` plus `GOOS=linux golangci-lint run`
(the repo's standing rule), and the real Linux test run stays with CI.

### Out of scope confirmations

`docs/qa/deep-hypervisor-qemu.md`, `TBX_E2E_HYPERVISOR`, `make e2e-all` and the per-cluster
balloon/suspend redesign stay with their sibling issues, as the plan says. The local e2e
battery in §3 is executed by hand on the development Mac and its results recorded in the PR.

## 1. Summary and delivery order

Deliver #535 before enabling the Darwin QEMU factory from #536.

The selection/state work must land first because the Darwin registry will expose two hypervisors, and every create/start/status path must already resolve the correct per-cluster backend before that happens.

The implementation keeps these invariants:

- `clusters[].hypervisor` overrides `TBX_HYPERVISOR`, which overrides the compiled default.
- The effective choice is persisted in `cluster.Cluster.Hypervisor` at create.
- Persisted state always wins for an existing cluster.
- A legacy empty state value means the platform’s compiled default, not the current environment-selected default.
- A silent YAML key expresses no desired change and therefore never causes drift.
- An unavailable hypervisor is a capability gate: it does not prevent `tbxd` from starting, but create/start against it returns its reason.
- `tbx-helper` remains unchanged.
- Linux QEMU argv and the tap attachment path remain byte-for-byte unchanged.
- No `ProtocolVersion` bump is made; the new status/info fields are additive and `omitempty`.
- User-facing text consistently uses the glossary term “hypervisor”.

### Registry contract

Extend `Registry` from its current effective-default-only form:

```go
type Registry struct {
    Backends        map[Name]Backend
    Default         Default
    CompiledDefault Name
}
```

`newRegistry` records `selection.Name` in both `Default.Name` and `CompiledDefault`. Environment selection changes only `Default`; `CompiledDefault` remains immutable for legacy state resolution.

Add:

```go
const DefaultEnv = "TBX_HYPERVISOR"

const (
    DefaultSourceCompiled    DefaultSource = "compiled"
    DefaultSourceEnvironment DefaultSource = DefaultEnv
)

func ParseName(raw string) (Name, error)

func (r Registry) WithDefault(raw string, source DefaultSource) (Registry, error)
```

`ParseName` accepts only `vz` and `qemu`. It returns:

```text
hypervisor must be one of vz | qemu (got "xen")
```

`WithDefault` must:

- parse the global name;
- require it to be registered for the current platform;
- allow a registered-but-unavailable backend;
- update `Default` without changing `CompiledDefault`.

A nonempty unknown daemon environment value is fatal configuration:

```text
TBX_HYPERVISOR: hypervisor must be one of vz | qemu (got "xen")
```

Treat an unset or empty `TBX_HYPERVISOR` as no override, leaving source `compiled`.

Extend `Availability` with:

```go
Remediation string
```

Add a small package-private typed unavailable error or constructor that carries `Reason`, `Remediation`, and an optional wrapped error. `newRegistry` recognizes it and populates both fields. Ordinary backend errors continue to populate `Reason` and `Err` as today.

`Registry.Resolve` continues returning `ErrUnsupported` and the reason. Remediation is diagnostic metadata for doctor, not part of operational errors.

### Three-stage availability probe

Run in this order:

1. Binary on `PATH`.
2. `-accel help` lists the exact line `hvf`.
3. Host authorization: `kern.hv_support == 1` and QEMU carries `com.apple.security.hypervisor`.

Only after those pass, run the shared QMP version/machine probe and firmware discovery.

Use exact reason/remediation families:

| Failure | Reason | Remediation |
|---|---|---|
| Binary absent | `<binary> was not found on PATH` | `install QEMU: brew install qemu, then restart tbxd` |
| HVF not compiled | `QEMU does not list the hvf accelerator` | `HVF not built in: Homebrew builds without HVF on macOS 14; upgrade to macOS 15+ and reinstall QEMU` |
| Host sysctl denied | `HVF denied: kern.hv_support is not 1` | `use a Mac with Hypervisor.framework support enabled` |
| Entitlement absent | `HVF denied: <binary> lacks com.apple.security.hypervisor` | `install or reinstall a signed Homebrew/nixpkgs QEMU; do not re-sign it without the hypervisor entitlement` |
| Firmware absent | `no matching EFI firmware pair found for <arch>` | `reinstall QEMU so its edk2 firmware is present` |

Command/sysctl execution failures preserve the underlying error while retaining the stage-specific remediation.

Parse `-accel help` by trimmed whole lines, so `hvf` is accepted but a substring such as `whvf` is not.

## 4. Risks and open questions

### Protocol 20 is unchanged

Risk: a development-only daemon built from the #534 baseline also reports protocol 20 and would ignore a new request field.

Recommended resolution: honor the explicit no-bump requirement. Require the normal same-build `tbx`/`tbxd` deployment and document restarting `tbxd` after upgrading. Do not invent protocol 21 solely for additive status/info fields.

### Registered but unavailable effective default

Risk: `TBX_HYPERVISOR=qemu` on a Mac without QEMU makes the effective default unavailable.

Recommended resolution: keep `tbxd` running and show the gate through doctor. Creation without an explicit VZ override fails with the QEMU reason; an explicit `hypervisor: vz` remains usable.

### Empty legacy state versus environment default

Risk: treating empty state as the effective default would silently migrate old VZ clusters to QEMU after an environment change.

Recommended resolution: retain `Registry.CompiledDefault` separately and resolve legacy state only through it. Never materialize a platform value in `cluster.Load`.

### Homebrew and Nix firmware layouts

Risk: Cellar/store hashes change during upgrades, and launchd PATH may not contain `brew`.

Recommended resolution: prefer the symlink-resolved binary’s sibling `share/qemu`, then the live `brew --prefix` result, then stable Homebrew/Nix profile roots. Never consume Homebrew’s versioned descriptor JSON.

### Entitlement output stability

Risk: human-readable `codesign` output has changed across macOS releases.

Recommended resolution: request XML explicitly and parse it structurally with `encoding/xml`. Treat malformed output as an unavailable gate with reinstall/signing remediation.

### QEMU 6.2 versus datagram netdev history

Risk: `-netdev dgram` appeared after the project’s general QEMU 6.2 floor, while the design explicitly keeps version floors unchanged.

Recommended resolution: do not raise the shared floor in these issues. Current Homebrew/nixpkgs Darwin QEMU is newer; keep the three-stage availability contract and surface an operational launch error on an unexpectedly old custom Darwin build. Revisit only with a real supported-host reproducer.

### Darwin QMP peer credentials

Risk: using only PID would miss a same-PID-reuse/UID boundary; using only UID would accept another same-user process.

Recommended resolution: require both `LOCAL_PEERPID` and `LOCAL_PEERCRED.Uid`, matching the current Linux PID+UID check.

### Intel Mac support

Risk: the code can compile and probe `darwin/amd64`, but no Intel host is available for real validation.

Recommended resolution: register QEMU and label Intel best-effort/community-verified. Do not put it on the parity bar or claim a VZ backend there.

### Clean stop behavior

Risk: Talos may not answer `system_powerdown` promptly, causing the existing timeout path to kill QEMU.

Recommended resolution: retain the current bounded fallback and require the local HVF battery to demonstrate normal clean exit. Do not add a second stop mechanism without a reproducer.

### Balloon and suspend scope

Risk: touching daemon balloon/suspend logic could duplicate #534 or collide with later sibling issues.

Recommended resolution: make no new daemon abstraction. Rely on the existing per-cluster calls, expose QEMU’s existing capabilities under HVF, and regression-test mixed balloon eligibility plus restart-safe suspend. Leave automated hypervisor-parameterized e2e targets and soak coverage to their designated follow-ups.
