- QEMU suspend support already advertises restart-safe restore when the probed version is new enough: `qemuCapabilities()` sets `Suspend.Supported=true` and `SuspendSurvivesDaemonRestart=true` at or above the suspend floor (`internal/hypervisor/qemu_probe.go:126-147`).
- `savedStateStale()` is already per cluster capability, not host-wide: clusters whose backend reports `SuspendSurvivesDaemonRestart` are never marked stale; others fall back to the owner-sidecar check (`internal/daemon/suspend.go:578-625`).

Thus a plain `tbx system restart` still refuses for a suspended QEMU cluster even though the backend can restore it.
- Existing tests prove pieces of this, but not the mixed-registry AC:

## 6. Risks and open questions

1. `balloonablesFrom()` bypasses the injected probe seam today.
   - Risk: mixed-host tests either become slow/flaky or require awkward live probing.
   - Recommendation: thread `probe func(string) ProbeResult` through `balloonablesFrom`; that is a narrow, testability-first change grounded in the existing `Server.nodeProbe` field.
2. Fatal-vs-fallback restore policy for QEMU needs to be explicit.
   - Risk: if all `ErrIncompatibleSave` paths become fatal, corrupted-but-recoverable saves may stop cold-booting.
   - Recommendation: make only header/identity mismatches fatal; keep runtime migrate/incoming failures on the fallback path unless product intent changes.
3. Doctor’s “best-effort platform” note must not corrupt availability semantics.
   - Risk: overloading `AvailabilityReason` would blur “available but best-effort” with “unavailable because gated”.
   - Recommendation: derive it in a pure/testable doctor renderer from GOOS/GOARCH + backend name; transport only the genuinely missing `Suspend` feature gate.
4. Intel macOS CI runner selection is external to the repo.
   - Risk: a guessed `runs-on` label will churn the workflow.
   - Recommendation: confirm the current Intel runner label when implementing `ci.yml`, but keep the job body identical to the existing macOS lane.
5. `TBX_E2E_HYPERVISOR` and `make e2e-all` are in the design doc but not yet in `Makefile`.
   - Risk: trying to land that makefile work inside these three issues will broaden the diff and collide with CI/docs.
   - Recommendation: keep the current issues scoped to unit/fake tests plus the manual hardware script above unless maintainers explicitly fold the Makefile/e2e follow-up into this batch.
6. Restart safety must be conservative across compatibility boundaries.
   - Risk: a disk-only scan or old daemon cannot prove which backend wrote a save.
   - Recommendation: only a live daemon's explicit per-cluster restart-survival bit bypasses refusal; omitted/unknown/unavailable remains unsafe.
7. “Balloon readback” could tempt a public `Machine` getter refactor.
   - Risk: that would touch VZ and every fake despite no acceptance need; the daemon already maintains the applied-target ledger and QEMU already tests `query-balloon`.
   - Recommendation: keep the existing interface and use the capability only for eligibility/device-pending policy in this batch.
