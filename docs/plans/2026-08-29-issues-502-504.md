## Amendments

### #504 item 3 — balloon opt-out is documentation, not a spec knob **[amended]**

The issue offers two shapes: "a spec knob or a documented substrate-only patch". The plan's
knob (`talos.disableBalloon`) drags in daemon protocol 19, a generalised schematic composition
with kernel args in the cache identity, and cache-pull combination plumbing — roughly half the
#504 surface for an explicitly non-default escape hatch. Ship the documented path instead:
`docs/guest-memory.md` shows how to bring a schematic with
`customization.extraKernelArgs: ["module_blacklist=virtio_balloon"]` via `talos.schematic`
(console args must stay first) and states what tbxd loses. Steps 5–6 and the protocol-19
parts of steps 1–2 are dropped. If a first-class knob is still wanted, file it as a follow-up.

### #504 kubelet opt-out knob **[amended]**

`kubeletMemoryProtection: false` stays. Follow the exact precedent of the last
`ProvisioningIntentInput` knob (`hubble`): pointer input, validated through
`ParseProvisioningIntent`, rejected without `cni`, durable negative field on
`ProvisioningIntent`, and whatever protocol bump / client gate that precedent required —
no more.

### #504 kubelet defaults skip nodes under 2 GiB **[amended, review round 2]**

The plan's own risk note ("`systemReserved.memory: 512Mi` plus a `300Mi` eviction threshold is
material on 1 GiB workers") understated it: on a 1 GiB curated node the unconditional defaults
leave ~150 MiB allocatable and the cluster never reaches Ready. `withReclaimProtection` applies
the kubelet eviction/reservation defaults only when the role's memory is ≥ 2048 MiB
(`kubeletMemoryProtectionMinMiB`); the reclaim sysctls still apply to every node. Documented in
SPEC.md and guest-memory.md; covered by `TestGeneratedConfigSkipsKubeletMemoryProtectionOnSmallNodes`.

### #504 Nix vendorHash **[amended]**

`nix` is not installed on the development host. Leave `vendorHash` for the CI nix lane to
report and patch it from that output before merge.

## Issue #503 — Platform-aware full-tunnel detection

### Findings

- `HostRoute` currently carries only interface and network in [subnet.go](/Users/oyr/projects/talos-box/internal/cluster/subnet.go:19).
- The default-route branch warns only for an `utun` name in shared code at [subnet.go](/Users/oyr/projects/talos-box/internal/cluster/subnet.go:224).
- Linux already resolves the selected route’s `netlink.Link` at [subnet_system_linux.go](/Users/oyr/projects/talos-box/internal/cluster/subnet_system_linux.go:46), but discards `link.Type()` and `link.Attrs().EncapType`.
- Darwin parses `/sbin/route` through [systemRoute](/Users/oyr/projects/talos-box/internal/cluster/subnet_system_darwin.go:29), where retaining the `utun` convention is appropriate.
- Existing synthetic route coverage is concentrated in [subnet_test.go](/Users/oyr/projects/talos-box/internal/cluster/subnet_test.go:9). Linux netlink selection has only vanished-link/error tests in [subnet_system_linux_test.go](/Users/oyr/projects/talos-box/internal/cluster/subnet_system_linux_test.go:15).
- WSL2’s NAT default is an ordinary Ethernet `Device`/`ether` link and must remain non-warning.

### Design

Extend `HostRoute` with:

```go
LooksLikeTunnel bool
```

`inspectSubnet` should warn for a `/0` only when this bit is true. Shared code must not inspect platform-specific interface names.

Platform population:

- Linux: add `linuxLinkLooksLikeTunnel(netlink.Link) bool`, using positive metadata from both `link.Type()` and `LinkAttrs.EncapType`.
- Darwin: add `darwinRouteLooksLikeTunnel(string) bool`, preserving the `utun` prefix rule, and set the bit after `parseHostRoute`.
- Stub: return the zero-valued route and false bit.

Recommended Linux classifications:

- tunnel: `tuntap`, `wireguard`, `ppp`, `ipip`, `gre`, `gretap`, `sit`, `vti`, `vti6`, `xfrm`, plus corresponding `EncapType` values such as `ppp`, `ipip`, `tunnel6`, `gre`, and `sit`;
- non-tunnel: `device`/`ether`, bridge, VLAN, veth, dummy, loopback.

Do not add a name-prefix fallback on Linux. It recreates the defect for arbitrarily named WireGuard/corporate links and encourages false confidence.

Reject the “default interface differs from primary connectivity” heuristic for this issue. Determining “primary” needs an additional policy-sensitive route lookup and behaves poorly with multiple uplinks, policy routing, captive networks, and WSL. A positive tunnel signal is smaller and quieter.

### Design

#### Provisioning defaults

Add a pure scaling helper:

```go
func reclaimMinFreeKiB(memoryMiB int) int
```

Use:

```text
memoryMiB × 32 KiB
floor:   16 MiB = 16,384 KiB
ceiling: 256 MiB = 262,144 KiB
```

Examples:

- 512 MiB → 16,384 KiB;
- 1 GiB → 32,768 KiB;
- 2 GiB → 65,536 KiB;
- 4 GiB → 131,072 KiB;
- ≥8 GiB → 262,144 KiB.

For every curated-provisioning role config, merge defaults only when the key is absent:

```yaml
machine:
  sysctls:
    vm.min_free_kbytes: "<scaled>"
    vm.watermark_scale_factor: "200"
    vm.vfs_cache_pressure: "50"
  kubelet:
    extraConfig:
      evictionHard:
        memory.available: "300Mi"
      systemReserved:
        memory: "512Mi"
```

Existing values for those keys win. Preserve unrelated sysctls, kubelet settings, nested eviction thresholds, reservations, and existing extra mounts.

#### Kubelet opt-out

Add a cluster-level declarative knob:

```yaml
kubeletMemoryProtection: false
```

Keep it with `ProvisioningIntentInput`, because it only has meaning when tbx generates machine config for a curated CNI. Missing means enabled. Reject it when no `cni` is declared, like the existing provisioning-only knobs.

Persist the negative durable state internally, e.g. `DisableKubeletMemoryProtection bool`, so old cluster JSON defaults safely to protection enabled.

Do not expose a CLI flag in this issue; the requested surface is `talosbox.yaml`.

#### Balloon opt-in

Add the Talos-spec knob:

```yaml
talos:
  disableBalloon: true
```

It adds exactly:

```text
module_blacklist=virtio_balloon
```

to the Image Factory schematic. Do not expose arbitrary `extraKernelArgs`; that would make mandatory console ordering and cache identity user-controlled.

Generalize schematic composition so extra kernel arguments:

- are appended after `console=tty0`, `console=hvc0`;
- participate in the composition-record cache key and JSON record;
- work with zero curated extensions;
- are appended to an explicitly supplied base schematic only because this knob is explicit consent;
- remain reusable offline once recorded.

Persist the resolved schematic ID and `DisableBalloon` state. Existing tbxd `ErrTargetPending` handling remains unchanged.

#### Version bump

Update the actual default-bearing surfaces:

- `internal/talosversion.Default`;
- `github.com/siderolabs/talos/pkg/machinery`;
- docs default examples;
- KVM harness default/case/checksum;
- CI contract and tests;
- Nix `vendorHash`.

Do not mass-replace `v1.13.6` fixtures that intentionally test an arbitrary supported version. The official Talos installer derives its binary hash from the release’s `sha256sum.txt`; pin the `talosctl-linux-amd64` value from that artifact rather than computing it from an untrusted mirror. See the [official installer implementation](https://github.com/siderolabs/talos/blob/main/website/static/install).

Leave `controlplane.yaml` unchanged in this issue: it is an unused, generated credential-bearing sample, not a default source. Regenerating it would create a large unrelated secret/config diff. Record a follow-up to remove or replace it with a sanitized fixture.
