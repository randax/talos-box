# Implementation plan v2: issues #515, #514, #512, #471, and #468

## 1. Per-issue design

### #515 — Supervised restart refusal must name affected clusters

Current locations have drifted from the issue: `restartDaemon` calls `refuseSupervisedRestart` at `cmd/tbx/system.go:106` before `daemonClusterActivity` at `:112`; `restartRefusal` and `supervisionRefusal` are at `cmd/tbx/client.go:372-401`.

**Files to change**

- `cmd/tbx/system.go`
- `cmd/tbx/client.go`
- `cmd/tbx/daemon_restart_safety_test.go`
- `cmd/tbx/daemon_gate_test.go` only if shared protocol-gate expectations require adjustment

**Approach**

1. Reorder `restartDaemon` to perform:
   - the initial `daemonHandshake`;
   - existing `busyDaemonError` recovery, retaining the daemon PID;
   - bounded `daemonClusterActivity(socketPath)`;
   - the supervision decision;
   - the ordinary force/replacement path.
2. Split the current refusal text into composable pieces:
   - a reusable impact description naming running clusters, unsafe suspended clusters, and suspended-cluster recovery commands;
   - the existing unsupervised suffix offering `tbx system restart --force`;
   - a supervised suffix offering only `supervisorRestartCommand()`.
3. When supervision is confirmed and activity is non-empty, return one ordered error: cluster impact first, supervisor reason and command second. Do not mention `--force`, because confirmed supervision refuses every force level.
4. When supervision is confirmed and activity cannot be determined, state that the activity query failed before naming the supervisor command. The refusal must still be returned promptly and must not attempt replacement.
5. For inferred supervision, preserve current semantics:
   - without `--force`, name the cluster impact and both valid recovery choices;
   - with `--force`, allow in-place replacement.
6. On the unsupervised forced path, retain the on-disk VM-count fallback for stop-time scaling when `cluster.list` cannot answer.

**Chosen decisions**

- The activity query retains its existing short deadline: `runningClusters` calls `exchangeWithin(..., daemonHandshakeTimeout)` at `cmd/tbx/client.go:446-450`. No new timeout is required, and a wedged daemon cannot hang the refusal path.
- The supervised path explicitly tolerates `busyDaemonError`. The initial handshake continues with the recovered PID, the subsequent activity query is bounded, and confirmed supervision still produces the combined refusal instead of returning the busy error or attempting replacement.
- The combined confirmed-supervisor message does not reuse `restartRefusal` verbatim because its `--force` advice would be false.
- `packaging/linux/usr/lib/systemd/user/tbxd.service` remains unchanged. `KillMode=process` and QMP re-adoption remain out of scope.

### #514 — Periodically reassert DHCP desired state

`Converge()` is now reached through startup `ConvergeServices` (`cmd/tbx-helper/main.go`, `internal/helper/dhcp_manager.go`), `net.sync` (`internal/helper/server.go`), and `net.attach`. The remaining gap is `cmd/tbxd/networking_linux.go:23-26`, where Linux maintenance is still a no-op.

**Files to change**

- `cmd/tbxd/main.go`
- `cmd/tbxd/networking_linux.go`
- `cmd/tbxd/networking.go`
- `cmd/tbxd/networking_other.go`
- New `cmd/tbxd/helper_state_maintenance.go`
- New `cmd/tbxd/helper_state_maintenance_test.go`
- `internal/daemon/helper_sync.go`
- `internal/daemon/helper_sync_test.go`
- `internal/daemon/hermetic_host_test.go` only if the new seam requires a process-wide stub

**Approach**

1. Add `Server.TrySyncHelperState()` in `internal/daemon/helper_sync.go`.
2. `TrySyncHelperState()` uses `opMu.TryLock`. If a lifecycle or provisioning operation owns the daemon lock, the maintenance pass skips immediately rather than blocking.
3. After acquiring `opMu`, the method:
   - reads current cluster state with `listClustersForSync` while still holding the lock;
   - sends that exact snapshot through `SyncHelperClusters`/`net.sync`;
   - releases the lock only after the sync attempt completes.
4. This lock scope is mandatory: cluster state must not be read before acquiring `opMu`, and the lock must not be released between the state read and `net.sync`. A maintenance pass therefore cannot retain an old snapshot and overwrite reservations committed by a later node mutation or destroy.
5. Change `startHostNetworkingMaintenance` to accept the daemon server. Darwin retains its current resolver/forwarding maintenance and ignores the server; unsupported platforms remain no-op.
6. On Linux, run an injectable ticker at a one-minute cadence. Each tick calls `TrySyncHelperState`; helper unavailability or sync failure is logged and retried on the next tick.
7. Keep the existing startup `daemon.SyncHelperState()` in `cmd/tbxd/main.go:95-99`. It runs before the server accepts concurrent mutations and provides immediate recovery after daemon startup.

**Chosen decisions**

- The stale-snapshot race is prevented by holding `opMu` continuously across both the authoritative cluster-state read and its corresponding `net.sync`.
- Busy ticks skip rather than queue behind long operations.
- One minute is short relative to DHCP lease loss while avoiding high-frequency full-state pushes.
- The daemon remains authoritative for the current user’s clusters.
- No helper operation or wire change is introduced; the implementation reuses `net.sync`.

The Cilium QA path must prove the outer `/dial` URL still connects directly to `.200`, the source request reaches `lb-probe`, and the nested request reaches the sibling’s `.200` through `probe.<sibling-domain>`.

**Approach**

1. Add a disposable-host-only harness that refuses to run unless:
   - PID 1 is systemd and `systemctl is-system-running` reports `running` or `degraded`;
   - `/dev/kvm` is writable;
   - the caller has active `tbx` and `kvm` group membership;
   - the required CPU, memory, disk, and networking prerequisites are present;
   - no conflicting test clusters exist;
   - the operator explicitly opts into installing checkout assets under packaged system paths.
2. Build `tbx`, `tbxd`, and `tbx-helper`; install the existing `packaging/linux/` tree verbatim; run `systemd-sysusers`; reload system and user managers; and enable `tbx-helper.socket` and `tbxd.socket`.
3. Assert the live unit contract:
   - service user/group are `tbx`;
   - effective and bounding capabilities are exactly `CAP_NET_ADMIN`, `CAP_NET_BIND_SERVICE`, and `CAP_NET_RAW`;
   - `StateDirectory=tbx`, mode `0700`;
   - socket owner/group/mode are correct;
   - installed units and running binaries match the checkout.
4. Create the first disposable cluster and assert:
   - `/proc/sys/net/ipv4/ip_forward` is `1` after cluster creation;
   - `/proc/sys/net/ipv4/conf/br-tbx<n>/forwarding` is `1`;
   - `/var/lib/tbx/reservations.json` exists, is `tbx:tbx`, mode `0600`, and names the cluster, MAC, and reserved IP;
   - DHCP has a port-67 listener bound to the expected bridge;
   - `table inet tbx` contains the expected bridge/subnet rules;
   - the guest received its reserved address.
5. Create the minimal second running cluster needed for an actual forwarded-path test. Run the inter-cluster direct-IP and `/dial` matrix and require traffic to cross the host-managed routing/nftables path in both directions. A static sysctl value or host-only VIP curl is insufficient.
6. Exercise a normal `systemctl restart tbx-helper.service`.
7. Exercise the stronger #514 recovery:
   - stop the helper;
   - move aside `/var/lib/tbx/reservations.json`;
   - restart the helper with empty persisted state;
   - wait for periodic daemon `net.sync`;
   - require the reservation file and both DHCP listeners to reappear.
8. Stop and start a node after recovery and require the same reserved IP plus maintenance reachability, proving a real post-restart DHCP exchange.
9. Run unforced `tbx system restart` and assert the #515 refusal names the running cluster set followed by `supervisorRestartCommand()`, does not suggest `--force`, and does not restart the daemon.
10. Destroy both clusters and assert their bridges, nftables entries, DHCP listeners, and reservation entries are gone.
11. On failure, capture `systemctl status`, `journalctl`, `ss`, `ip`, `bridge`, `nft`, sysctl values, state-file metadata, daemon logs, and cluster status.

**Chosen decision**

Use a separate real-systemd harness and runbook. The existing KVM CI harnesses remain init-agnostic for Depot sandboxes. The static contract test permits and requires `systemctl` only in the new disposable-host harness.

## 5. Risks

1. **Cilium’s exact-host and wildcard resources could interact differently from the core matching contract.**

   Mitigation: avoid `defaultBackend`, pin and inspect the embedded 1.19.6 render, and require real-cluster proof that an exact attendee host overrides the talosbox wildcard while unmatched single-label hosts reach `lb-probe`.

2. **A Cilium probe call site could retain an IP-literal Host header.**

   Mitigation: unit-test `waitForProbe`, `LiveVIP`, `probeVIPFromHost`, and `probeVIPFromCluster` explicitly, reject redirects, and run the real direct-IP and `/dial` matrix.

3. **The nested `/dial` hostname could expose guest-side DNS assumptions.**

   Mitigation: test `probe.<sibling-domain>` resolution and the directed sibling matrix on real clusters. Treat failure as a release blocker rather than falling back silently to an IP Host that cannot match the wildcard Ingress.

4. **Trust installation may work for Go TLS clients but fail in browsers or leave stale roots.**

   Mitigation: use browser-facing OS stores, record exact fingerprints, test install/remove in browsers, document restart behavior, propagate macOS prompt cancellation, and keep NixOS declarative.

5. **The DHCP maintenance tick could overwrite newer reservations or block lifecycle work.**

   Mitigation: require `opMu.TryLock`, skip busy ticks, read cluster state under the acquired lock, and retain the lock through the matching `net.sync`.

6. **The systemd harness could pass without proving forwarding or could damage a development host.**

   Mitigation: require disposable-host opt-in and preflight checks, install packaged assets verbatim, assert both forwarding sysctls, and require real cross-cluster routed traffic rather than static configuration evidence.
